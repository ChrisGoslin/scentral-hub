CRITICAL SYSTEMS (Operations)
================================================================================

1. SHELF MODEL
   - 20 slots with S/A/B/C tiers (rank 1-20 maps to tier)
   - Eligibility trigger: Only Tested/Owned/Past-Purchase fragrances
   - If trigger blocks: backfill missing collections entry

2. IDENTITY MIGRATION (anon_id → user_id)
   - Runs on login via /auth/callback
   - Silently claims: temptations, shelf_events, evolution_events
   - Client-side: localStorage wishlist → collections(status='wishlist')
   - Both auth paths supported: auth.uid() + legacy anon_id

3. RATE LIMITING
   - Endpoint: POST /api/read/generate
   - Rule: Max 1 generation per hour per user
   - Returns: 429 when exceeded

4. BLIND BUY PROPAGATION
   - Trigger: set_blind_buy_on_reveal()
   - Marks blind_ranking entries as blind_buy=true if not in collections
   - Queryable for Insights ("Your blind buys outrank researched")

OPS SCRIPTS (Ready to Use)
================================================================================

📁 scripts/ops-*.sh — All scripts are executable and documented

  1. ops-migrations-verify.sh
     • Verify all 7 migrations are applied to Supabase
     • Run before launch, weekly

  2. ops-health-check.sh
     • Daily health check (deployment, API, build)
     • Runs in < 1 minute

  3. ops-claim-legacy-data.sh <user-uuid> <anon-id>
     • Manually claim user's legacy data (if auto-claim fails)
     • Requires confirmation before running

  4. ops-troubleshoot.sh <command>
     • rate-limits [days]      — Who hit rate limits?
     • shelf-ineligible        — Which fragrances blocked?
     • auth-claims <user-id>   — Did user claim data?
     • blind-buys <user-id>    — What did user blind-buy?
     • shelf-stats             — Aggregate metrics
